## 2. 产品概述

平台面向小学学校管理者、德育主任、班主任、学科教师、体育教师和家长，统一承载学生五育评价、班级评价、奖卡与荣誉积分、学科与体质健康成绩、活动参与、积分商城和学期报告。当前原型采用角色切换和本地演示数据模拟登录及数据持久化，重点验证多角色工作流与家长成长查看体验。

### 2.1 目标

- 将日常班级表现、五育奖卡、荣誉和活动成果沉淀为可追踪的学生成长记录。
- 让教师按权限快速完成评价录入、发卡、成绩导入、学期评语和活动管理。
- 让家长在一个入口内查看孩子的积分、历史成绩、体质健康、活动、荣誉和学期报告。
- 为德育主任和管理员提供班级、年级、教师和全校层面的数据看板与排行榜。

### 2.2 非目标

- 当前版本不定义真实统一身份认证、组织架构同步、服务端数据库、消息推送和正式报表归档方案。
- 当前学生端报名入口已关闭，活动报名由家长为绑定孩子完成。
- 当前原型中的学科、体测和历史学期快照为演示数据；正式上线时需接入教务和体卫艺数据源。

## 3. 用户与权限

| 角色 | 主要任务 | 可见范围与权限 |
| --- | --- | --- |
| 家长 | 查看孩子成长、报名活动、上传荣誉、积分兑换 | 仅查看已绑定孩子；可在多孩子之间切换；只读查看评价、奖卡、成绩和报告；可提交荣誉、活动报名与成果 |
| 班主任 | 管理班级评价、奖卡、荣誉、评语和学期评价 | 仅负责班级可录入班级/学生评价和奖卡；可上传教师荣誉；可审核所负责班级家长提交的荣誉；可查看所负责年级排行 |
| 学科教师 | 录入学科成绩、发放奖卡、填写学期评语 | 仅限配置的学科、班级和可发卡班级；不可进行班级评价 |
| 体育教师 | 发放体育相关奖卡、录入学科成绩、导入体质健康成绩 | 继承任课教师权限；可导入配置班级的体质健康成绩；支持按班级和男女生文件导入 |
| 德育主任 | 统筹年级评价、流动红旗、活动和数据 | 可评价所负责年级班级、发卡、配置流动红旗、查看数据看板和学校数据大屏、管理活动 |
| 管理员 | 全校配置、监督和运营 | 全班级、全年级、全部数据；可管理成绩录入任务、学期评价任务、积分商城、导出线下奖卡和全校运营数据 |

权限判断以教师角色、可评分班级、可发卡班级、可查看年级、可导入体测班级和任教科目/班级配置为准；家长身份始终不进入教师写入流程。

## 4. 信息架构与页面清单

- `/`：根据当前身份展示班主任首页、任课教师首页、管理员/德育主任首页或家长首页。
- 教师首页提供快捷进入班级评价、排行榜、奖卡、荣誉、活动、数据看板和成绩/评语任务。
- 体育教师首页的体质健康成绩进度按班级展示完整卡片；点击任意班级卡片直接进入成绩导入页，卡片区分班级完成状态及男生/女生文件状态。
- 家长首页包含孩子切换、积分总览、五育雷达、成长趋势、奖卡/荣誉/活动记录、学科成绩、体质健康、学期报告和积分商城入口。

- `/activities/enroll`：查看活动要求、报名时间、名额、积分条件并为孩子报名。
- `/activities/detail`：查看活动详情、报名状态、上传成果、填写实践/感悟和活动评价。
- `/points-mall`、购物车、结算、兑换记录：按孩子积分完成兑换及线下核销状态查看。
- 家长首页“学科成绩”和“体质健康”采用右侧侧边抽屉展示历史全部学期；最新学期默认展开，其余学期折叠。
- 家长首页“学期报告”采用右侧侧边抽屉展示报告，顶部支持学期切换，默认选中最新学期。

## 5. 核心业务流程

### 5.1 日常评价与积分沉淀

1. 教师进入班级评价，选择班级/学生、日期和指标。
2. 选择三级指标，系统显示默认分值；可录入备注和图片。
3. 提交后生成评价记录，记录操作者、时间、目标对象、加扣分类型和分值。
4. 班级排行榜按评价记录计算日/周/月表现；周榜以 100 分基准叠加加扣分。
5. 奖卡、荣誉、流动红旗奖励统一转为积分流水，按德、智、体、美、劳五育聚合。

### 5.2 奖卡与荣誉

- 线上奖卡按指标发放到学生，可批量选择学生；线下奖卡通过管理员批量录入/导出；流动红旗奖励可按班级全体学生生成奖励记录。
- 家长或班主任可提交荣誉，荣誉包含级别、名称、日期、颁发单位和图片；家长提交状态为待审核。
- 家长提交的荣誉只有班主任审核通过后才计入积分；待审核和驳回记录不进入积分聚合。

### 5.3 活动

1. 德育主任/管理员创建活动，设置标题、描述、面向年级/班级、报名窗口、活动时间、地点、名额和积分条件。
2. 活动状态由时间自动计算：未开始、报名中、进行中、已结束。
3. 家长在报名窗口内为绑定孩子报名；系统校验活动范围、重复报名、容量、积分余额和本学期五育积分门槛。
4. 报名记录进入待审核；审核通过后积分占用，驳回或取消时退还已占用积分。
5. 活动开始后允许提交图片、实践说明或感悟；活动结束后开放评价。

### 5.4 积分商城

- 管理员配置商品、上架状态、库存、兑换积分、适用年级和五育积分条件。
- 家长选择孩子后加入购物车并结算；系统校验商城开放时间、商品状态、库存、年级、商品条件和可用积分。
- 兑换成功后扣减库存并生成兑换记录；管理员可标记线下核销状态。

### 5.5 家长成绩与学期报告

- 家长首页快捷入口展示当前绑定孩子。
- 点击“学科成绩”或“体质健康”打开右侧抽屉；抽屉展示全部历史学期，按最新到最早排序。最新学期默认展开，其他学期使用可访问的折叠分组。
- 学科成绩按学期展示各科总分、等级及分项成绩；体质健康按学期展示综合评分、等级、身高、体重、肺活量、50 米跑、坐位体前屈、立定跳远、1 分钟跳绳和视力。
- 点击“学期报告”打开报告抽屉，学期选择器默认定位最新学期；切换学期后，五育发展、学科成绩、体质健康、荣誉、活动和班主任评语随选中学期刷新。

### 5.6 学期评语与学期评价管理

- 管理员进入学期评价管理后，在与成绩录入管理一致的单一工作台容器内切换“学期评语”和“学期评价”。
- 工作台保留任务卡片、发布任务、任务详情、教师/班主任进度、批量提醒和 localStorage 演示持久化；切换只改变当前任务模式，不改变既有任务数据。
- 页面采用与成绩录入管理一致的主色标签页、圆角边界、任务卡片和进度条层级；发布与详情仍使用抽屉/对话框承载复杂操作。

## 7. 数据对象与业务规则

| 对象 | 核心字段 | 规则 |
| --- | --- | --- |
| Teacher / ParentUser | 身份、角色、可评分班级、可发卡班级、可查看年级、绑定孩子 | 权限由角色与范围字段共同决定 |
| Grade / SchoolClass / Student | 年级、班级、班主任、学生、学号、性别 | 学生归属一个班级；家长通过 studentId 绑定 |
| ScoreRecord | 班级、日期、指标层级、entries、总分、目标学生、备注、图片、操作人 | `scoreType` 区分加/扣分；可作用于班级或学生 |
| AwardCardRecord | 学生、指标、五育、分值、日期、来源、操作人 | 来源包括 online、offline_scan、flag_reward |
| HonorRecord | 学生、五育、级别、名称、日期、颁发单位、图片、审核状态 | pending/rejected 不计入积分；approved 才计分 |
| Activity / Enrollment | 活动时间、范围、容量、积分条件、报名状态、审核信息 | 活动状态由时间推导；通过后占用报名积分 |
| MallProduct / MallRedemption | 商品、库存、价格、适用年级、条件、订单、核销 | 兑换成功扣库存；线下核销独立记录 |
| AcademicScore | 学科、总分、等级、分项成绩 | 学期报告和学科成绩抽屉均按学期展示 |
| FitnessMetrics | 综合分级、身高、体重、肺活量、跑步、柔韧、跳远、跳绳、视力 | 体质健康抽屉和学期报告共用同一学期快照 |
| SemesterReport | 学期、五育积分、学科、体测、荣誉、活动、班主任评语 | 报告选择器切换整份学期数据 |

积分规则：积分流水由奖卡和审核通过的荣誉构成；按周、月、本学期过滤；本学期定义沿用当前原型的学年周期逻辑。商城兑换和活动报名产生积分消耗/占用，余额为累计获得减去已消耗积分。

## 8. UX 与无障碍要求

- 延续现有浅色数据看板风格：蓝色为主色，绿色/橙色表示成长与提醒，卡片和抽屉使用清晰边界与分组层级。
- 所有抽屉、对话框和折叠学期分组必须支持键盘聚焦、Esc 关闭、可读标题和屏幕阅读器描述。
- 折叠分组使用原生 `details/summary` 语义或等价的 `aria-expanded` 控件；最新学期默认展开但用户可自由展开其他学期。
- 抽屉打开后焦点进入内容区域，关闭后返回触发入口；不得依赖悬停才能发现信息。
- 表格必须有表头和隐藏 caption；状态不能只用颜色表达；文字对比度不低于 WCAG AA。
- 桌面端抽屉宽度适配内容，移动端占满宽度；内容超出时内部滚动，页面背景不横向滚动。
- 空数据、加载中、错误、无权限和提交成功均需给出明确的中文反馈。

## 9. 非功能需求

| ID | 需求 | 目标 |
| --- | --- | --- |
| NFR-001 | 响应式布局 | 支持 375px、768px、1024px、1440px 视口；抽屉不产生横向滚动 |
| NFR-002 | 性能 | 家长首页首屏可交互；历史学期数据按需计算，不阻塞抽屉打开 |
| NFR-003 | 可访问性 | 键盘可操作、焦点可见、表格有语义表头、图表提供文本替代 |
| NFR-004 | 数据一致性 | 切换孩子或学期后，页面所有指标、列表和报告字段使用同一选择上下文 |
| NFR-005 | 兼容性 | 保持 Next.js 静态导出能力，现有路由和旧报告入口继续可用 |
| NFR-006 | 原型持久化 | 当前演示数据沿用 localStorage；正式版需替换为服务端接口和审计日志 |

## 12. 风险、依赖与待确认事项

### 风险

- 当前原型使用 localStorage，清理浏览器数据会导致演示记录恢复为种子数据，不代表生产数据持久化能力。
- 当前历史学期成绩和体测快照由确定性演示逻辑生成；正式数据接入后需确认学期编码、成绩发布时间和历史数据补录策略。
- 权限目前通过前端角色切换模拟，正式版必须由服务端鉴权与数据权限再次校验。

### 依赖

- 学校组织架构、班级学生名册、教务成绩系统、体质健康成绩来源。
- 五育指标、奖卡指标、流动红旗和班级评级规则的校方确认。
- 积分商城实物库存、兑换地点和线下核销流程。

### 待确认

1. 正式环境的学期边界是否固定为“8 月至次年 1 月/2 月至 7 月”，以及学期报告的历史保留年限。
2. 学科成绩是否需要展示原始分项、评价等级、教师评语和发布时间。
3. 体质健康成绩是否需要支持多次测试记录、测试日期和趋势图。
4. 家长提交荣誉的图片审核、隐私脱敏和单张大小限制。
5. 报告切换学期后，历史荣誉/活动为空时是否展示“无记录”，还是展示历史系统补录数据。

## 13. 后续同步规则

以后修改原型时按以下顺序同步：

1. 先更新本 PRD 的页面清单、用户流程、功能需求或数据对象；新增需求使用递增的 `FR-*`、`NFR-*`、`AC-*` 编号。
2. 修改权限时同时更新“用户与权限”矩阵和相关验收标准。
3. 修改表单、抽屉、弹窗或页面状态时，补充默认、空、加载、错误、成功和无权限状态。
4. 修改积分、报名、兑换或报告计算时，更新业务规则、数据对象和验收标准。
5. 在“变更记录”登记版本、日期、变更内容，再同步修改原型代码。
